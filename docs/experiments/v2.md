# V2：解耦取指、分支预测与时序优化

2026 年 10 月 15 日实现，基于 V1 提交 `82cb3f8`。在相同默认后端、Cache 容量和课程评测条件下，六项性能程序的 IPC 几何平均由 **0.1173 提升到 0.2462（2.10 倍）**，综合估算频率由 **44.52 MHz 提升到 85.77 MHz（1.93 倍）**。Mac 与课程 Linux 的全部 19 个正确性程序和 6 个性能程序均通过，周期逐项相同。

总面积由 **9,063.421 增至 11,948.045 μm²（增加 31.8%）**。当前结果仍低于课程性能档的 IPC 和 300 MHz 门槛；本次交付是可回归的第二版单发射 CPU。总体规划见 [arch.md](../arch.md)，初始基线见 [v1.md](v1.md)，精确参数、源码校验值与结果见 [v2-results.json](v2-results.json)。

## 实现变化

| 部分 | V1 | V2 |
| --- | --- | --- |
| 取指 | 一笔在途请求、单项缓冲 | 4 笔在途请求、8 项指令 FIFO；上下文保存 PC 与预测下一 PC |
| 预测 | PC+4 | 64 项直接映射 BTB、完整 PC tag、两位方向计数器；提交时训练 |
| I Cache | 阻塞式命中交付 | 同步 SRAM 流水命中，每拍可接受/交付一条，最多 4 个总信用 |
| D Cache | 请求后另拍启动 SRAM 查询 | 请求握手沿启动命中读取，仍只接收一笔 CPU 数据事务 |
| 外存读取 | 全局一笔；一行逐字等待 | 16 个总信用，AR 输出寄存器与有序来源 FIFO，行内请求连续发送 |
| IQ | 查询 PRF ready，串行比较最老候选，遍历 ROB 找老 Store | 本地就绪位与 WB 广播；并行年龄比较；每条 Load 保存更老 Store 的槽位掩码 |
| 执行级 | 调度、PRF 读取、执行、写回同一组合路径 | 在选择/读取后寄存操作数和元数据；执行受阻时保留整条指令 |
| 恢复 | 提交组合路径直接清空与重建空闲表 | 误预测指令先提交，下一拍恢复；用已提交物理寄存器位图回收 |
| 物理实现 | 大数组动态读写与共享控制 | PRF/ROB 逐项写使能，BTB/Cache tag 本地比较，Cache tag 逐行写使能 |

仍为单分配、单选择、单写回、单提交的乱序核；ROB=16、PRF=48、IQ=8、LSQ=8、I/D Cache 各 2 KiB、16 B 行、直接映射。迭代 MDU、单数据请求、Load 不越过更老 Store、Store 在 ROB 头等待 B 响应的策略保持。尚无 Store Buffer、访存转发、提前分支恢复、RAS、多发射或多路相联 Cache。

新增文件是 `verilog/frontend/fetch_frontend.sv` 与 `verilog/memory/icache_pipeline.sv`，正式清单已经接入。新增顶层参数：`FETCH_QUEUE_DEPTH=8`、`FETCH_OUTSTANDING=4`、`BTB_ENTRIES=64`、`PREDICT_ENABLE=1`。I Cache 的 4 个信用与前端参数分别约束本模块接收能力，超出时正常背压。`ISSUE_WIDTH`、`ICACHE_WAYS`、`DCACHE_WAYS` 仍只支持 1。

## 必须保持的正确性边界

1. **已接受请求必须排空。** 取指重定向清空指令 FIFO，并排空所有旧请求才发出最新目标；连续重定向也不能复用旧上下文。被杀 Load 的 LSU 上下文保留到返回，迟到结果不访问已复用的 ROB/PRF。任何填充字出错都完整排空整行，再向 CPU 报错且不安装该行。
2. **分支提交先于恢复。** 误预测提交时锁存实际目标并更新 RRAT/已提交位图；下一拍 `recovery_pending` 屏蔽年轻提交、Store、分配、选择及写回，再恢复 RAT、空闲表与队列。JAL/JALR 自身的 link 写入因此被保留。
3. **就绪状态与数据同步。** IQ 插入显式考虑同拍 WB；已有 IQ 项在下一拍观察广播就绪，此时 PRF 已写入。Load/MDU 抢占唯一写回口时，普通 EX 指令保持，直到实际执行才产生 ISSUE/COMPLETE。
4. **Store 顺序按槽位生命周期维护。** Load 分配时快照全部更老 Store 的 ROB 槽位；Store 退休清除相应位，新分配还扣除同拍退休位。外部 Store 仍只从 ROB 头发送。

普通构建 `TRACE=0`；诊断构建保留原有提交轨迹，并新增 `WB_STALL`、`RENAME_BYPASS` 事件验证执行级保持及同拍唤醒。所有调试状态排除在综合之外。

## 性能与时序证据

统一条件：`LATENCY=10`、相同测试子模块 `29f980727f7d99a1842a58f34091c7579ba3fe85`，IPC 使用课程动态指令数除以总周期。V2 预测开/关对照只改变 `PREDICT_ENABLE`，其余参数不变。

| 程序 | V1 周期 | V2 周期 | V1 IPC | V2 IPC | V2 关闭预测 IPC |
| --- | ---: | ---: | ---: | ---: | ---: |
| median | 59,734 | 28,504 | 0.1165 | 0.2442 | 0.1823 |
| multiply | 140,369 | 31,815 | 0.1547 | 0.6828 | 0.2837 |
| qsort | 1,238,315 | 653,354 | 0.1130 | 0.2141 | 0.1795 |
| rsort | 1,608,397 | 980,858 | 0.1217 | 0.1995 | 0.1843 |
| towers | 51,066 | 42,526 | 0.1034 | 0.1241 | 0.1204 |
| vvadd | 44,488 | 17,953 | 0.1017 | 0.2520 | 0.1908 |
| 几何平均 | — | — | **0.1173** | **0.2462** | **0.1844** |

在相同 V2 结构中打开预测，IPC 几何平均再提高约 **33.5%**。关闭预测的 V2 也优于 V1；该对照不能进一步区分取指、Cache 和后端各自的独立贡献。

课程 Yosys 0.63 / ASAP7 / OpenSTA 3.1.0，`MODE=opt`，目标周期仍为 2 ns：

| 指标 | V1 | V2 最终 |
| --- | ---: | ---: |
| 总面积（μm²） | 9,063.421 | 11,948.045 |
| 组合逻辑面积（μm²） | 4,059.101 | 5,112.769 |
| 时序逻辑面积（μm²） | 3,628.379 | 5,459.335 |
| SRAM 面积（μm²） | 1,375.941 | 1,375.941 |
| 估算最高频率 | 44.52 MHz | **85.77 MHz** |
| 最小周期 | 22.4600 ns | **11.6592 ns** |
| 最差建立时间裕量 | −20.4596 ns | −9.6583 ns |

这是课程的理想时钟、无布线寄生综合估算，未达到 2 ns 时序目标。没有修改综合脚本、库、约束、工具版本或 SRAM 模型来改善数字。

时序优化遵循实际报告：V1 的 ROB head 到调度、PRF 选择和写回控制横跨一个周期，高扇出占主要延迟。PRF 固定项写还避免了 Yosys 将 48 项动态写数组扩展到 64 项寄存器。

第一轮 V2 功能虽通过，但 BTB 和 I Cache 动态宽字选择器共享 `next_pc[4]`，正反网络合计驱动 5,311 个负载，估算频率仅 19.43 MHz。将 BTB 与 I/D tag 改为逐项比较后达到 83.59 MHz；进一步将 I/D tag 写改为每行本地使能，最终达到 85.77 MHz。后两步全部官方程序周期不变，收益来自组合逻辑结构。这也说明加入流水级后仍必须检查新出现的扇出瓶颈。

最终最差路径仍由 D Cache REFILL 状态经过整行完成条件，驱动本地 tag 写使能后到达 tag 寄存器。ABC 将共同完成条件共享到 982 个负载，高扇出及其引发的下级输入转换延迟仍占主导；这是真实待优化项，不能把加入 EX 寄存级等同于后端时序已经收敛。

## 验证与复现

最终默认配置通过 **26 组 × 延迟 1/10/31 = 78/78**，逐条比较 **63,741 次架构提交**。在原有全部测试上加入预测循环退出、JALR 目标变化、BTB 别名、执行级写回争用和访存顺序回绕五组测试。默认覆盖检查不降级：逐条架构提交、真正乱序发射、错误路径发射/取消、旧 Load 返回前 PRF 复用、预测训练与恢复、EX 保持及同拍唤醒均须满足。Mac/Linux 的精确故障诊断分别 **27/27** 通过。

小配置使用 ROB=5、PRF=37、IQ=3、LSQ=3、I/D=128 B、行=8 B，前端队列=5、在途=3、BTB=5：**26 组 × 延迟 1/10 = 52/52** 通过，比较 **42,494 次提交**。它保留逐条提交比对，只豁免依赖默认窗口时序和 BTB 布局的覆盖；具体配置与启用检查记入结果 JSON。

执行单测覆盖 Decoder 4,035 项、ALU 6,628 项、M 运算 2,257 项与取消/背压；存储单测覆盖 16/64 B 行、长短延迟、I 命中逐拍收发、4/16 信用耗尽与回绕、I/D 公平、AW/W 独立握手及错误填充排空。前端五配置单测覆盖非 2 的幂、最小容量、预测关闭、背压和连续恢复，默认可连续 158 拍交付指令。参考模型/覆盖比较器 13 项单测与 26 组 GNU 机器码编码核对通过。

```sh

tools/dev linux perf SIM=build/linux/sim MAX_CYCLES=100000000

# 单元测试与逐提交回归
```

完整回归需显式增加周期上限；当前 `correctness_pi` 为 40,366,931 周期。官方文件、测试与评测脚本未改。最终综合保存在 `build/v2/synth-r3/opt/`，中间设计保存在独立目录，受版本管理的精简测量与验证证据在 [v2-results.json](v2-results.json)。
