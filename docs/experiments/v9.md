# V9：乘法提前结束与商余数复用

V9 对应旧称 `v7-mdu-speed`，是面向 OJ 长程序的乘除优化版本；后续由 [V10](v10.md) 替换乘法结构并增加除法前导零优化。版本对应关系见 [文档索引](../README.md)。

本版基线为 `11d9ff5` 的 [V8](v8.md) RTL（文档提交 `054579b` 未改变硬件）。最终生产改动位于 `muldiv_unit.sv`、`cpu_core.sv` 和 `youngest_match.sv`：实现乘除优化，并调整转发匹配与访存计数逻辑以保持 500 MHz。顶层参数、Cache 和综合约束保持基线配置，官方构建脚本、官方仿真器及官方测试程序未修改。

## 为什么优化乘除单元

独立 RV32IM 参考模型执行原始 `correctness_pi/program.data`，得到结果 112，共退休 3,117,658 条指令。其中 MUL 为 562,600 次，DIV 和 REM 各为 281,600 次，REMU 为 1 次。原单元固定迭代 32 次，这些有效操作需要 36,025,632 次迭代，而原整机程序为 39,421,922 周期。

乘数有效位数平均为 11.9003，最多为 14；架构执行顺序中有 281,600 次除法操作与上一次除法的原始操作数及有符号模式相同。这些统计用于选择优化方向，不等同于乱序硬件的实际复用命中次数，也不作为最终加速比。

## 乘除实现

乘法保留 64 位移位累加算法。当前最低位参与累加后，若剩余高 31 位均为零，当前部分和就是完整乘积，立即形成结果。最多仍为 32 次迭代，零乘数执行 1 次。MUL/MULH/MULHSU/MULHU 的幅值、符号修正及高低半部选择保持正确。

非零除法保留 32 次恢复算法。正常完成时同时保存经过符号修正的商、余数、两个原始 32 位操作数及有符号模式。后续请求只有在两个操作数和模式都相同时才能复用，支持 DIV/REM、DIVU/REMU 双向复用及重复相同运算。乘法和除零旁路不替换这项记录。

匹配结果与请求操作数一起寄存，命中请求在第一个 `DIVIDE` 上升沿形成结果。宽比较不直接控制请求接收时的状态跳转。未命中的非零除法仍迭代 32 次；除零仍在接收边沿直接形成 ISA 规定的结果。

单元保持一笔在途请求。结果受背压保持，消费结果与接收下一请求分开。`reset` 和 MDU `flush` 优先取消事务并清除复用记录有效位；完成边沿同时取消时不会安装有效记录。无效载荷无需复位。

## 为满足 500 MHz 保留的结构调整

首版只修改 MDU 时，完整官方正确性已经通过，但全芯片重新映射后的频率仅为 476.279070 MHz。V8（S23）的时序余量较小，因此不能沿用旧版的频率结论。经过以下筛选，最终版本满足全部门槛：

| 候选 | 频率 MHz | 总面积 μm² | 结果 |
| --- | ---: | ---: | --- |
| 仅乘除优化 | 476.279070 | 32271.175 | 频率不合格 |
| 省略无效转发数据清零 | 485.308057 | 32466.357 | 频率不合格 |
| 普通/绕回候选并行树（弃用） | 478.728378 | 32371.748 | 频率不合格 |
| 前移 Store 字地址比较 | 496.846191 | 33758.320 | 频率不合格 |
| 预计算待发送计数（最终） | 501.469148 | 33800.573 | 采用 |

最终保留三项不增加执行周期的调整：

1. **前移 Store 字地址比较。** 每个 IQ 候选用其保存/唤醒地址与旧 Store 并行比较，年龄选择直接选匹配位图。该位图同时用于选择拍 Load 的数据冲突检查和转发；旧 EX Load 保持自己的比较路径。接受 Load 时断言核对它与原表达式一致。
2. **独立保存转发有效性。** MQ 已保存逐字节掩码，未匹配字节不会参与 Load 合并，因此选择器在这里省略无效数据清零门控。模块默认仍输出零，新增可选模式经形式检查。最终选择算法保留原平衡淘汰树，普通/绕回双树候选未采用。
3. **提前计算待发送计数。** 从寄存值生成 `−1、+1、+2` 候选，Load/Store 入队与 Cache 握手只选择净变化，避免晚到握手串行经过加减。运行时断言和局部 SAT 检查均核对原“入队数减发送数”公式。

最终最小可行周期为 **1.994140625 ns**，2 ns 目标下最差 setup 裕量为 **+0.006602 ns**。总面积中，组合逻辑 14,678.721 μm²、时序逻辑 7,310.120 μm²、SRAM 11,811.732 μm²。

综合沿用 `MODE=opt`、ASAP7、ABC `BUFx2_ASAP7_75t_R / 1 fF`；OpenSTA 输出负载 5 fF，目标 2 ns，I/O 延迟各 0.2 ns，时钟不确定度、时钟转换和输入转换各 0.05 ns。采用课程 ideal-clock/no-parasitics 模型。验收条件为频率 ≥ 500 MHz、总面积 ≤ 36,000 μm²、六项 IPC 几何平均 ≥ 1.0985。

两项定向程序原来依赖固定 32 拍 MDU 延迟制造事件碰撞。现在通过改变除法操作数避免复用，并使用完整 32 位乘数保持长乘法，恢复原有响应/恢复碰撞和双通路覆盖。**检查器和覆盖条件没有放宽，官方测试文件没有修改。**

本轮复用了源码未变的 MDU 单元结果，其他最终筛选与回归记录均核对 V9 冻结源码。未改动的存储单元、其他执行/前端单元及无关形式证明未重跑，其历史结果保留在 [V8 验收记录](v8-results.json)。本版源码、工具、完整约束、候选测量和日志摘要见 [V9 验收 JSON](v9-results.json)；[arch.md](../arch.md) 描述后续 V10 的当前结构。

## 复现

先准备与 [V9 验收 JSON](v9-results.json) 的源码摘要一致的独立副本，再在课程 Linux 容器内使用官方入口。直接在当前 V10 工作树运行会测试 V10：

```sh
make CONFIG=config.linux.mk build BUILD=build/v9/check JOBS=3
make CONFIG=config.linux.mk test perf BUILD=build/v9/check \
  SIM=build/v9/check/sim LATENCY=10 MAX_CYCLES=100000000
make CONFIG=config.linux.mk synth SYNTH_OUT=build/v9/check/synth MODE=opt
```

若需运行仓库既有完整发布矩阵（也包含本轮未重复的存储和前端单元等），使用：

```sh
python3 verification/runners/run_v7_linux.py \
  --out build/v9/full-reproduce --jobs 3 --target v7-500
```

`--out` 应为新目录；容器须具备 Git。原始本轮记录位于 `build/v7-mdu-speed/`，其中最终官方回归在 `candidate/`，综合在 `synth/opt/`，未采用候选分别归档。
