# V7 正式实现与 Linux 验收

本页记录 2026-10-19 的 V7 正式发布，属于历史版本。后续 500 MHz 时序优化独立编号为 [V8](v8.md)，当前实现为 [V10](v10.md)；完整演进与旧名对应关系见 [文档索引](../README.md)。

2026-10-19，V7 原型已集成到生产目录 `verilog/`，`student_top` 默认选择 V7 参数。使用课程 Linux 容器完成官方正确性、逐提交性能、全量定向、兼容参数、故障和单元回归，并对同一份 RTL 重新综合。三项验收门槛全部满足。

| 课程 STA 估算频率 | **314.786351 MHz** | > 300 MHz | 14.786351 MHz |

完整机器可读记录见 [v7-results.json](v7-results.json)，包含参数、源码与镜像 SHA-256、逐项结果、定向覆盖证据、工具版本和原始日志索引。集成基于设计资料提交 `b4a8952`；V6 对照为 `a66193614d8ac59b606eb41d0ed973a0cbc3c7e2`，测试子模块固定为 `29f980727f7d99a1842a58f34091c7579ba3fe85`。设计筛选与历史原型数据保留在 [v7-design.md](v7-design.md)，本页记录生产 RTL 的重新验收结果。

## 集成内容

- 两条选择通路：A 服务整数、访存地址和乘除，B 服务整数与控制流。支持双整数、整数与访存、整数与分支、访存与分支；每拍最多选择两条指令。
- 第二重命名位置支持 Load、Store、MDU、分支与跳转。同步维护两笔访存信用、同组 RAW/WAW 和 older-Store 掩码；每拍最多分配一个控制检查点。
- 第二提交位置支持 Load、MDU、控制流和 RAM Store。每拍最多一个 Store 入队、一个预测器更新，MMIO 保持队首串行化。
- Store 先计算地址，数据按物理寄存器身份在稍后捕获。Load 等待未知旧 Store 地址；非别名 Load 可越过已知地址但数据未就绪的 Store，同字冲突则等待。转发仍逐字节选择最年轻旧 Store。
- 阻塞 Load 在真正接受前保留 IQ 项、释放 EX 并重试，避免挡住旧 Store 的数据生产者。恢复按年龄保留旧工作，取消的请求继续按原身份排空。
- 就绪 RAM Load 可在选择拍进入持久访存队列，分支执行拍可直接重定向前端，下一拍恢复后端。提前 Load 的载荷准备和有效控制分开，地址采用已证明等价的 16+16 位 carry-select 加法。

主要代码为 [cpu_core.sv](../../verilog/cpu_core.sv) 与 [student_top.sv](../../verilog/student_top.sv)。生产可综合逻辑与已选定 R4 原型一致，新增 `SELECT`、`STORE_ADDR`、`STORE_DATA`、`LOAD_RETRY`、`EX_KEEP` 等验证事件均处于 `ifndef SYNTHESIS` 区域，不参与综合。

| 部件 | 默认配置 |
| --- | --- |
| 取指 / 重命名 / 选择 / 提交 | 2 / 2 / 2 / 2 |
| ROB / PRF / IQ | 32 / 64 / 12 |
| LSQ / 持久访存队列 | 16 / 16 |
| 分支检查点 | 8 |
| 取指 FIFO / 在途请求 | 16 个指令字 / 4 笔 |
| I Cache | 2 KiB，直接映射，128 B 行 |
| D Cache | 32 KiB，4 路，256 B 行，写回与写分配 |
| 预测器 | 64 项 BTB，XOR 索引，bimodal/local1 混合，提交训练，RAS 关闭 |

## 性能、频率与面积

官方 `TRACE=0` 构建和验证用 `TRACE=1` 构建得到完全相同的六项周期。后者用独立 RV32IM 参考模型核对全部 **374,104 条架构提交**。

| 程序 | 动态指令数 | 周期 | IPC |
| --- | ---: | ---: | ---: |
| median | 6,961 | 8,624 | 0.807166 |
| multiply | 21,722 | 16,694 | 1.301186 |
| qsort | 139,900 | 132,395 | 1.056686 |
| rsort | 195,719 | 121,282 | 1.613751 |
| towers | 5,278 | 5,317 | 0.992665 |
| vvadd | 4,524 | 4,535 | 0.997574 |

IPC 按六个精确的“指令数 / 周期”取几何平均，外存 `LATENCY=10`，计入原框架的复位、填行和退出排空时间。官方程序、计数、退出协议、`scripts/`、构建规则和评测约束均未修改。

仿真使用课程 Linux aarch64 容器的 Verilator **5.020**、Python **3.12.3**；综合使用 Yosys **0.63** 与 OpenSTA **3.1.0**，`MODE=opt`。ABC 仍为 `BUFx2_ASAP7_75t_R / 1 fF`；STA 输出负载 **5 fF**，目标周期 **2 ns**，输入/输出延迟各 **0.2 ns**，时钟不确定度和转换时间各 **0.05 ns**。最小可行周期为 **3.1767578125 ns**；逻辑面积 **18,905.769 μm²**，SRAM **11,811.732 μm²**，两者合计为上表总面积。

频率是原课程理想时钟、无布线寄生模型的估算，不是布局布线后的签核频率。2 ns 目标下的负裕量表示没有达到 500 MHz，不影响按最小可行周期核验 300 MHz 门槛。IPC 余量仅约 0.155%，后续改动必须重跑完整六项，不能只比较四舍五入到四位的显示值。

五组兼容参数分别为：非二次幂小队列与小缓存、全单宽、关闭提前恢复与并行完成、关闭提前 Load 与执行拍重定向、只关闭并行完成而保留提前恢复。完整参数保存在结果 JSON 和 `run_v7_linux.py`。兼容配置只跳过依赖默认流水窗口的计时覆盖，不能替代默认 189 项的严格验收。

官方 19 项正确性采用官方输出协议；本次完整逐提交核验覆盖六项性能及所有定向/兼容程序。设计阶段 R2 的 19 项逐提交记录继续作为历史资料保留，没有算作本次 Linux 同源逐提交结果。

### 关键覆盖与测试平台修正

V7 新增 11 个程序，严格证明真实双选择与非整数双退休、第二位置 JALR 检查点、SB/SH/SW 晚到数据、别名 Load 重试和非别名越过、旧 Load 跨恢复继续执行、错路 Store 在 ROB 槽位复用后不得捕获晚到结果。每个证据都绑定动态指令身份并核对最终是否提交，不能用错误路径上的同 PC 事件代替。

旧 EX 保留另用 `PARALLEL_COMPLETION=0`、提前恢复仍开启的组合触发：`selective_response_collision` 在延迟 1/10/31 下均使动态指令 196 在分支 200 恢复时停留于 EX，分别在第 460/520/856 拍被保留，下一拍唯一执行并完成，随后唯一提交。结果 JSON 保存每个延迟的具体事件。默认配置的阻塞 Load 则通过 IQ 重试跨恢复，两种路径分别验证。

两个单完成口配置会出现 Verilator `UNOPTFLAT` 告警：Store 数据旁路读取 `wb_available`，而同一个 `always_comb` 中还计算 `issue_simple`，过程块级依赖形成伪环路。两组配置分别通过 Yosys `proc; flatten; opt; scc -expect 0; check -assert`，逐信号结果均为 0 个实际组合环路，并各通过 189 项回归。默认 V7 构建没有该告警；原始告警和结构检查日志均保留。

`SELECT` 检查每拍两条的真实选择宽度。`ISSUE` 表示不同流水级的执行接受，早 Load 与上一拍 A/B 操作可能同拍出现三个接受事件；检查器仍要求每个动态身份只接受一次，重复选择必须有中间的 Load 重试。逐字节转发检查按当拍全部存活旧 Store 重建最年轻写者，允许来自前一次循环的合法旧 Store，拒绝年轻 Store 的数据。

原 V6 的时序刺激在 V7 上不能覆盖所有原有义务，已调整预热与真实生产者依赖，并把检查点饱和改为 **8+1**。默认验收没有关闭 OoO、错误路径在途取消、恢复响应碰撞或物理寄存器复用检查。

32 KiB 四路缓存的同组间隔为 **8 KiB**，CPU 冲突测试按此调整；退出排空程序按 **256 B** 步长写脏 256 行。写回单元测试的旧 64 KiB 模型内存不足以容纳新容量下的冲突地址，已仅对较大缓存测试扩为 128 KiB。正式 CPU RAM、外存延迟与性能测试口径保持原样。最终全矩阵在这些修正后重跑通过。

## 复现与审计

先准备与 [V7 验收 JSON](v7-results.json) 的源码摘要一致的独立副本，再在课程 Linux 容器内、仓库根目录运行以下入口。直接使用当前工作树会测试 V10。输出目录必须不存在；省略 `--out` 会自动生成时间戳目录。

```sh
python3 verification/runners/run_v7_linux.py --out build/v7/release --jobs 3
```

本项目 macOS 环境可从仓库根目录启动相同课程容器：

```sh
docker --context colima-cpu2026 run --rm --platform linux/arm64 \
  --mount "type=bind,source=$(pwd),target=/work" --workdir /work cpu2026:arm64 \
  python3 verification/runners/run_v7_linux.py --jobs 3
```

入口依次执行官方测试、V7 生成器、逐提交回归、兼容构建、故障注入、检查器自测、程序审计、单元测试、形式等价及综合。保存每步命令与退出码，并比较执行前后的源码摘要，最后由 `collect_v7_results.py` 核对矩阵完整性、二进制源码清单、测试镜像、官方/trace 周期一致性和三项门槛。测试失败、源码变化或门槛未达都以非零状态退出。

本次验收由同源的各分项命令完成，汇总脚本已在最终产物上成功执行；新总入口编排这些相同命令，没有把尚未执行的总入口整次运行冒记为额外一轮验收。正式日志位于 `build/v7/linux-final/`，汇总可重做：

```sh
python3 verification/runners/collect_v7_results.py \
  --runs build/v7/linux-final --memory-directory memory-units-r2 \
  --out docs/experiments/v7-results.json
```

`build/` 是本地生成产物；版本管理中的结果 JSON 保存实测值、覆盖证据和摘要，重新运行总入口可生成新的完整日志。详细测试约定见 [验证说明](../../verification/directed/README.md)。
