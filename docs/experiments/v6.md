# V6：成对取指与非对称双发射

基于 V5 提交 `f372fa7`，实现成对取指、最多双重命名/双提交、整数与复杂操作并行发射，以及 Load 与提交 Store 同拍入队。同步上游前的默认配置达到 **IPC 几何平均 > 0.845、频率 > 300 MHz、总面积 ≤ 18,000 μm²**。完整测量、源码 SHA-256、参数与验证索引见 [v6-results.json](v6-results.json)，当前结构见 [arch.md](../arch.md)。

## 当前项目测试配置（2026-10-19）

根据上游 README 的可配置 ABC 示例，项目统一使用 `ABC_DRIVING_CELL=BUFx2_ASAP7_75t_R`、`ABC_LOAD_FF=1.0`。配置集中于 `config.synth.mk`，由普通 Make、Mac、Linux 三个入口共同包含，命令行仍可覆盖。

同一 V6 RTL 的新结果为 **IPC 几何平均 0.867648、课程估算 608.437314 MHz、总面积 17,776.466 μm²**，同时满足原三个目标。面积距上限余 **223.534 μm²**，2 ns 目标下 setup slack 为 **+0.356780 ns**。OpenSTA 输出负载保持 **5 fF**，其余时钟/I/O 约束、标准单元库及 SRAM 模型也保持不变；更改的仅是 ABC 映射参数。

三组 Make 配置的默认值及官方默认命令行覆盖均验证通过，Mac/Linux 环境自检与两组样例综合通过，六项官方性能周期逐项不变。完整来源、对照值和配置摘要见 [当前配置结果](v6-abc-config-results.json)。下文保留官方默认对照与旧综合流程的历史数据。

## 默认配置与发射边界

| 结构 | V6 默认值 |
| --- | --- |
| 宽度 | `FETCH_WIDTH=RENAME_WIDTH=ISSUE_WIDTH=COMMIT_WIDTH=2` |
| 后端 | ROB 16 / PRF 48 / IQ 6 / LSQ 8 / 持久访存队列 8 / 分支检查点 4 |
| 前端 | FIFO 8 个指令字，最多 4 笔请求，BTB 64，1 位局部历史混合预测，RAS 关闭 |
| I Cache | 2 KiB，直接映射，128 B 行，64 位同步数据 SRAM |
| D Cache | 16 KiB，4 路，256 B 行，写回/写分配 |
| 恢复与旁路 | 选择性提前恢复、响应直通、Load 请求旁路、并行完成、Store 并行入队均启用 |
| 重定向 | `REDIRECT_OVERLAP=1`、`REDIRECT_REQUEST=0`；恢复后一拍起请求新路径，旧请求继续排空 |

这是非对称双发射：普通整数指令使用整数通路，分支/JAL/JALR、访存和 M 扩展使用复杂通路；两路可同拍发射。不能同拍发射两条普通整数，也不能同拍发射两条访存。第二重命名位置、第二提交位置均仅接受普通整数指令。单条乘除仍迭代执行，Cache 仍各自最多一个缺失。

顶层默认值即最终配置，无需额外实验参数。各宽度支持 1/2；独立 `cpu_core` 默认宽度仍为 1，以保留窄配置兼容性。顶层在 RAS 非零、I 行长或容量小于 8 B 时自动回退单字取指。小缓存实验应分别覆盖 I/D 行长，不能只改旧公共 `CACHE_LINE_BYTES`。

## 结构改动

**成对取指。** 地址按 8 B 对齐、首条预测顺序执行且有足够容量时，一个请求带回两个 32 位指令；否则只使用一个字。两个位置分别查询 BTB，保存各自预测。取指队列按“指令字”预约容量，请求描述符按“请求”计数，取消后仍保留原事务身份直到响应排空，避免双字响应溢出队列或混入新路径。支持只消费第一条、FIFO 空时双字直通，以及 FIFO 剩一条时接入下一响应的第一条。

I Cache 数据阵列改成 64 位同步 `sram_fakeram`，32 位写粒度分别填入两个 lane；总位数不变，SRAM 面积的微小尾数差来自模型舍入。Miss 必须等待整行所有响应及错误合并，两字共享该请求的完整错误结果。末拍出错不能让已到达的首字提前成功返回。

**双重命名与双提交。** 两条同时分配时获得不同 ROB/IQ/PRF 项；第二条的 RAW 直接映射到第一条新物理目的，WAW 的旧映射正确串接。退休同拍写同一架构寄存器时，年轻条更新 RRAT 的优先级最高，同时释放各自正确的旧物理寄存器。第二条故障、控制或访存指令留待下拍成为第一条处理，保持原故障与提交边界。

**两个独立发射选择器。** IQ 保存成对年龄关系，各通路独立选择自己的最老就绪项，避免“先选第一条、再排除它选第二条”的串行延迟。整数通路增加执行、完成、PRF 写入、IQ 唤醒及操作数旁路，支持自身连续相关指令和跨通路依赖。已有选择/读数寄存边界保留。IQ 从 8 项收敛到 6 项，控制新增选择与旁路的成本。

**选择性恢复扩展。** 分支检查点包含分支自身的重命名结果，但排除同拍第二条年轻指令；JAL/JALR 链接和同组 WAW 不会被年轻映射污染。恢复保留老 IQ、Load、Store、乘除上下文，取消年轻项并回收其物理目的。两路在恢复检测时停止继续选择；恢复拍暂停架构提交与完成，旧响应按原契约保持或排空。

**Load 与提交 Store 并行入队。** 持久队列有两个空项时，执行 Load 放在第一项，提交的 RAM Store 放在第二项。Load 在该拍保存包含退休 Store 的逐字节转发快照，因此即使 Store 的 ROB 项释放，也不会丢失原始值来源。后续请求按队列顺序观察已提交 Store；MMIO Store 继续串行化。仍禁止 Load 越过未知 Store。

**时序收敛。** 双译码释放的 FIFO 信用到下一拍重新使用，切断译码/重命名到 Cache 请求的组合反馈路径；两个队首使用旋转 one-hot 选择。恢复请求保留寄存边界，取指载荷与有效控制分离。PRF、ROB、IQ、取指与访存队列继续按项写使能，空闲项可预采样，只有实际握手建立有效状态。保留 ROB16/PRF48，以维持旧长操作与恢复的重叠空间；最终频率、面积和 IPC 均来自这一配置。

已退休 RAM Store 的晚到错误仍按持久描述符中的原 PC/指令诊断并停止，不回滚已经退休的年轻指令。未扩展自修改代码、缓存一致性、陷阱处理、多 MSHR 或推测越过未知 Store 的契约。

小参数为 ROB5/PRF37/IQ3/LSQ3/MEMQ3/检查点3，I/D 各 128 B、行长均 8 B、D 单路，取指 FIFO5/在途3/BTB5/RAS3。小参数与单宽回归关闭依赖默认结构的时序覆盖要求，保留架构逐提交、顺序和访存身份检查；不能用这些兼容结果替代默认配置的 156 项严格验收。

宽度测试检查真实动态身份及最终提交。`wide_rename_retire` 在每个延迟下观察到 **129** 次双分配、**66** 次双发射、**208** 次双提交，并覆盖同组 RAW/WAW；`wide_checkpoint_pair` 实际观察 JAL 与年轻 WAW 同拍分配、年轻项取消和链接值恢复。双取指覆盖部分消费、请求/响应背压、取消、第二位置跳转、非对齐错误及行尾错误后的重新填行。

V6 的 `--recovery-mode wide` 生成配置调整三个 LSU 用例的指令间隔，并扩大 MDU 恢复响应碰撞扫描，使新流水线实际触发原有严格要求。两笔已接受在途 Load、同一次取消两笔请求、已退休 Store 跨恢复存活，以及旧 MDU 响应在恢复拍被保持等门槛保持不变。原 `selective`/`legacy` 生成模式保留。新双取指测试的部分消费计数使用握手边沿前采样，避免把边沿后已经出队的第二字误计为没有出现。
