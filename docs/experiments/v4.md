## 实现与默认配置

ROB=16、PRF=48、IQ=8、LSQ=8 保持不变；取指 FIFO=8、在途=4、BTB=64。默认 I Cache=2 KiB/直接映射，D Cache=16 KiB/4 路，行长=128 B。所有数据/标签继续使用原同步 SRAM，未把 SRAM 替换为理想组合存储。

- **8 项持久访存队列**：发送与响应独立推进，可同时保存多个 Load、已提交 RAM Store。响应严格按序；flush 仅标记推测 Load 为 killed，保留描述符直到响应排空，避免 ROB/PRF 复用污染。
- **已提交 Store 缓冲**：RAM Store 在 ROB 头入队即退休；队列保留地址、数据、字节掩码和诊断身份，后续恢复不能取消。MMIO Store 保持串行，直到响应才从 ROB 退队。
- **逐字节转发**：Load 等待所有更老 Store 的地址和数据就绪；对每个字节选择最年轻的更老匹配 Store。可合并多个 SB/SH/SW；无冲突 Load 可越过已解析 Store。已退休 Store 在有序队列中先于后续 Load，依靠 Cache 本地更新顺序保证可见性。即使完全转发，仍进行 Cache 请求，在响应处合并。
- **D Cache 命中流水**：最多 4 笔 CPU 信用，Load 命中每拍接收一条，Store 命中每两拍一条，最短响应延迟 2 拍；响应 FIFO 保持有序与背压稳定。缺失仍阻塞新请求，尚无多个 MSHR。
- **流水整行写回**：同步 SRAM 每拍读出一个 word，经小 FIFO 送入 16 信用写桥。128 B 行共 32 个 word，信用耗尽时正确暂停/恢复，所有 B 排空成功后才清脏。MMIO 扫描中每 8 条全清洁行一拍跳过。
- **同拍写回唤醒与旁路**：IQ 选择可使用当前写回结果，操作数直接捕获旁路值。候选载荷选择不经过全局 flush，实际发射与状态写入仍受取消约束。
- **提前正确路径取指**：EX 检出误预测后先重定向前端并暂停分配，后端仍等该分支到头提交后恢复 RRAT。若更老分支随后发现错误，覆盖年轻目标；提交恢复优先于年轻 EX 请求。已准备正确路径可保留，完整后端提前恢复尚未实现。

实现了可选 RAS，支持 x1/x5 返回提示和推测恢复；默认 `RAS_DEPTH=0`。16 项 RAS 对这些性能程序收益很小，64 B 行对照仅 towers 减少 11 周期，因而不承担其寄存器与提交路径成本。I Cache 从 2 KiB 增至 4 KiB 对照没有改善周期，也保持 2 KiB。

## 访存与错误契约

所有 uncached/MMIO 请求必须等待之前已接受请求的响应，Cache 再完成全组、全路清脏后才发送外部请求。退出写不会越过缓冲 Store，先前 Store 发生错误时退出请求也不能漏到外部。测试在退出 AW 时检查外存字节，并确认之前所有写响应已经排空。

脏行写回失败时，完整排空已经发送的行请求，保留原标签与所有脏字节，不安装替换行、不发送本次后续 MMIO。被杀 Load 的晚到错误只排空，不能更新复用后的物理寄存器。

已提交 RAM Store 的响应可能晚于其 ROB 槽位复用。如果发生错误，CPU 使用队列保存的原 PC/指令报告 `buffered_store=1` 并停止；不会回滚已经提交的年轻指令。这是异步 fail-stop 错误，不是精确 Store 陷阱。未提交 Load 和串行 MMIO Store 继续在安全提交点诊断原有精确故障。课程范围仍不含 CSR 陷阱处理、自修改代码、FENCE、缓存一致性或热复位保存脏数据。

首轮 V4 综合仅 250.98 MHz，路径从恢复控制经写回仲裁、IQ 唤醒和发射选择到 EX。把候选写回与最终有效性分离，并将 ROB 提交读取改为旋转 one-hot 队首后，达到 270.76 MHz。此时最长路径经 Store 入队仲裁到寄存器回收；但写目的寄存器与重定向指令均不可能是 Store，因此单独计算这两种提交资格，移除不必要的访存依赖，并以断言检查与原提交表达式等价。随后达到 288.05 MHz，余下瓶颈为恢复经访存入队驱动宽载荷写使能。访存队列改为空闲队尾预写载荷，使用不含取消控制的 Load 候选选择数据，实际有效位仍只在真实入队时更新；满队列及已有描述符保持不变。最终达到 300.205 MHz。按搜索结果，距 300 MHz 的周期余量约 2.28 ps；保持同样 I/O 约束单独设置 300 MHz，直接 STA 最差裕量为 +2.6967 ps。两者因 0.001 ns 搜索分辨率略有差别，均仅刚达标，不代表物理实现也可达到该频率。

最终 Load 从 Cache 实际接收至响应的平均延迟，在六程序中约为 2.00～3.25 周期；从核心入队到 Cache 接收另有约 1.75～3.50 周期等待。两段明确分开；Store 入队退休、Cache 请求和响应也使用独立事件，不把已经提前退休的 Store 服务时间误算为退休停顿。后续应重点评估分支恢复、队列等待与缺失阻塞；最终关键路径为访存队列已发送/未完成计数经响应资格、写回候选、IQ 唤醒和年龄选择到 EX 载荷，仍可继续压缩选择深度。各项停顿可能重叠，不能直接相加得到 CPI。

## 正确性验收

最终同一源码在 Mac Verilator 5.052 与课程 Linux Verilator 5.020 均通过 **19/19 正确性和 6/6 性能程序**，所有周期逐项一致；常规精确故障两平台各 **27/27**。两平台执行与前端单测各 **10/10**，包含原五项前端配置与额外 RAS 深度 0/1/3。

默认 43 组 × 延迟 1/10/31：**129/129**，逐条比较 **98,298 次提交**。六性能程序另比较 **374,104 次提交**。ROB=5、PRF=37、IQ=3、LSQ=3、MEMQ=3、I/D=128 B、行=8 B、D=1 路、前端=5/3/BTB5、RAS=3 的非二次幂配置 **86/86**，比较 **65,532 次提交**；仅豁免依赖默认窗口时序的覆盖，架构逐条比较与事务检查均保留。

写回故障注入 **12/12**。Decoder **4,035**、ALU **6,628**、M 运算 **2,257** 项与取消/背压通过；原生写回存储 **14** 组、旧写穿 **3** 组，Linux 最终 16 KiB/128 B 行快慢两组通过。覆盖连续请求、独立 AW/W 背压、16 笔写信用及 32-word 写回中途暂停恢复、尾部 B 错误、全组全路清脏和退出前外存检查。参考模型/分析工具 **23/23**，全部 **43** 组 GNU 编码独立核对通过。

新增测试不仅比较最终输出，还验证真实事件：两笔 Load 被 Cache 连续接受；恢复后两笔旧响应被取消，其中一个目的寄存器已经复用；Store 在退休后跨越分支恢复仍写入；多条 Store 的部分字节合并及年龄反向场景；早取指被更老分支覆盖，以及年轻重定向与老分支提交同拍。写回故障注入保留原有 9 项，并新增 3 项缓冲 Store 异步错误，故意延迟响应到 ROB 多次复用后检查原 PC、已退休前缀和 MMIO 屏障。

官方构建、测试、综合脚本、SRAM 模型、约束、标准单元库、配置和测试子模块均未修改。
