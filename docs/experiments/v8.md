# V8：500 MHz 时序优化与 Linux 验收

V8 对应旧称 **V7-500MHz / S23**，基线为 [V7](v7.md)，后续版本为 [V9](v9.md)。本页为 V8 历史验收；当前架构见 [V10 架构文档](../arch.md)，版本关系见 [文档索引](../README.md)。

优化前的分析见 [V8 方案](v8-plan.md)，过程与失败候选见 [V8 候选记录](v8-experiments.json)。S1、S2、S23 是 V8 内部候选编号。

## 正式验收

2026-10-20，基于 V7 提交 `690c35ba5f61a6015766e5db1c3a8893b611ebde` 完成生产 RTL 时序优化。默认参数、缓存容量、流水拍数、官方测试及课程综合约束保持原样；V7 的六项性能周期全部不变。冻结同一份源码完成完整 Linux 功能矩阵、形式证明和最终综合，三项新门槛均满足。

| 指标 | 最终实测 | 要求 | 余量 |
| --- | ---: | ---: | ---: |
| IPC 几何平均 | **1.1002013686** | ≥ 1.0985 | 0.0017013686 |
| 课程 STA 估算频率 | **504.185130 MHz** | ≥ 500 MHz | 4.185130 MHz |
| 总面积，含 SRAM | **32,287.898 μm²** | ≤ 36,000 μm² | 3,712.102 μm² |

最小可行周期为 **1.9833984375 ns**，2 ns 目标下最差 setup 裕量为 **+0.017544 ns**。逻辑面积为 **20,476.167 μm²**，SRAM 仍为 **11,811.732 μm²**。ABC 驱动及负载、STA 的 5 fF 输出负载、0.2 ns I/O 延迟及 0.05 ns 时钟约束均沿用首次发布设置；频率仍属于课程理想时钟、无布线寄生口径。

## 候选 S1、S2 的独立验证

| 阶段 | 单项变化 | 频率 MHz | 总面积 μm² | 周期与定向检查 |
| --- | --- | ---: | ---: | --- |
| S1 | 整数年龄计数改为平衡零/一判定树 | 333.441876 | 30,731.031 | 六项周期不变，189/189 |
| S2 | 在 S1 上分离提前 Load 地址准备与准入控制 | 341.333333 | 30,892.578 | 六项周期不变，189/189 |
| S23 | 按后续关键路径收敛的最终生产版本 | 504.185130 | 32,287.898 | 六项周期不变，完整 Linux 验收通过 |

S1、S2 的周期与逐提交筛选使用原生 Verilator，综合均使用课程 Linux 环境。S1 对宽度 1/3/5/12/16/24/32 的候选和年龄掩码完成 SAT 等价证明；S2 保留旧 EX Load 优先、队列背压下的数据归属、准入授权和同拍 Load/Store 入队检查。两步可分别由 [S1 补丁](v8-s1.patch) 和 [S2 补丁](v8-s2.patch) 在上述基线上依次重放，已验证重放后的 RTL 与对应实测快照逐字节一致。

全部 **28 个候选**及退步对照保存在 [v8-experiments.json](v8-experiments.json)，包含父版本、精确指标、六项周期和源码/报告摘要。最终主要保留以下结构改动：

- 将完整整数计数替换为零/一判定树，逐字节 Store 转发改为平衡的最年轻匹配选择；完成身份比较与访存队列头选择并行展开。
- 将 Load、Store、Cache 安装和请求地址的载荷准备与晚到有效控制分离。D Cache 采用直接命中位数据选择、与同步标签同时预读的有效位及独立安装标签，实际请求授权规则保持不变。
- 用位级并行前缀加法器处理 ALU、地址和分支目标；Store 字节对齐使用独立选择器，消除综合资源共享把 Store 准入条件串到 ALU 移位与下一条 Load 地址前的问题。
- 在 IQ 内保存就绪 Load 的有效地址，同拍唤醒时并行准备旁路地址；分支重定向地址在误预测比较前准备，让前端查询与比较并行。最后一步使频率由 S22 的 471.021159 MHz 提升到 504.185130 MHz，没有增加执行或恢复拍数。

## 最终 Linux 验证与复现

| 验证 | 通过结果 |
| --- | ---: |
| 官方正确性 / 性能 | **19/19、6/6** |
| 默认严格定向 / 五组兼容配置 | **189/189、945/945** |
| 架构与总线故障 / CPU 写回错误 | **27/27、12/12** |
| 存储单元 / 执行与前端单元 / Python 检查器 | **69/69、32/32、46/46** |
| 形式等价证明 / 单完成口组合环路检查 | **18/18、2/2** |

严格逐提交比较合计 **1,019,098 条**。18 项 SAT 证明覆盖生产加法器、全部 ALU 操作码、合法 Load 立即数与地址、Store 字节对齐，以及七种宽度的年龄谓词与最年轻字节转发。两个单完成口配置均为 0 个组合环路。新增运行时断言核对地址缓存、队列身份、旧 EX 优先、重定向载荷和 Cache 端口归属。完整输入摘要共 **164 项**，验证前后完全一致；生产目录的独立综合复核与最终综合也得到相同面积、频率和关键路径。

正式产物位于 `build/v7-500/linux-final/`，机器可读记录为 [v8-results.json](v8-results.json)。首次总入口的测试、证明和综合步骤全部返回 0；末尾汇总因课程运行镜像未安装 Git，读取版本号时失败。随后仅在一次性容器中安装 Git，保持源码和测试产物不变，重新执行原汇总脚本并通过全部门槛。原失败、成功重试及原因均保存在 `steps.json`、`acceptance.log`、`acceptance-retry.log` 和 `qualification-completion.json`，没有把原总入口退出码改记为 0。

复现 V8 前先准备与 [V8 验收 JSON](v8-results.json) 的源码摘要一致的独立副本，确保课程 Linux 容器内有 Git，并使用新的输出目录。当前 V10 工作树不会复现 V8 的历史测量：

```sh
apt-get update
apt-get install -y --no-install-recommends git
python3 verification/runners/run_v7_linux.py \
  --out build/v8/reproduce --jobs 3 --target v7-500
```

`--target v7-500` 要求 IPC ≥ 1.0985、频率 ≥ 500 MHz、总面积 ≤ 36,000 μm²，并检查最小周期 ≤ 2 ns、2 ns 下 setup 裕量非负、原课程约束及综合输入摘要。默认 `--target v7` 保留首次发布的门槛。
