# V3：写回 Cache、并行写回与关键路径收敛

基于 V2 提交 `3e8f93f`，保留单发射乱序后端，主要改进访存串行等待和控制信号的高扇出。历史基线见 [V2](v2.md)，当前完整架构见 [arch.md](../arch.md)，精确参数、源码校验值和验证结果见 [v3-results.json](v3-results.json)。

最终 IPC 几何平均为 **0.30925（较 V2 提高 25.6%）**，课程综合估算最高频率 **338.96 MHz（3.95 倍）**，总面积 **10,792.602 μm²（减少 9.7%）**。300 MHz 目标已达到；IPC 仍低于课程性能档的 0.6000 下限，不能据此认为性能档全部条件已经满足。

## 结构变化

| 部分 | V2 | V3 |
| --- | --- | --- |
| D Cache | 2 KiB、单路、写穿、不写分配 | 4 KiB、4 路、写回、写分配；优先空路，满组 round-robin |
| Cache 标签 | 触发器阵列 | I/D 标签与数据均用同步 `sram_fakeram`；valid/dirty 留在逐行更新的触发器 |
| 外存写入 | 一笔 AW/W/B 完成后才接下一笔 | 4 笔描述符；AW/W 各自按序握手，按 B 回收信用 |
| 脏行写回 | 无 | SRAM 逐字读出与多个未完成写请求重叠，整行响应排空后才继续 |
| Load 调度 | 旧 LSU 返回后再选择下一笔 | 返回当拍选择下一笔，次拍 EX 执行；仍仅一笔 CPU 数据上下文 |
| 控制路径 | 恢复、真实握手直接驱动多组宽数据保持 | 有效状态与载荷分开；空闲项预采样，局部资源状态控制 EX 保持 |
| BTB 训练 | 提交到 BTB 的组合更新 | 提交训练寄存一级，逐行更新；已提交训练不因重定向取消 |

ROB=16、PRF=48、IQ=8、LSQ=8；I Cache 仍为 2 KiB 直接映射，行长仍为 16 B。前端仍为 8 项 FIFO、4 笔在途、64 项 BTB。未增加 Store Buffer、多数据事务、Store-to-Load 转发、多发射或提前分支恢复。

写回 D Cache 支持 1/2/4 路；`DCACHE_WRITE_BACK=0` 保留单路写穿实现，方便旧协议测试与对照。正式默认参数在 `verilog/student_top.sv`。

## 访存与错误边界

Store 只有在 ROB 头获得不可撤销授权后才访问 D Cache，命中时在 SRAM 更新后返回并退休。Load 继续保存更老 Store 的槽位掩码；Load 不越过它们。移除调度中重复的 `store_start` 条件依赖于这个年龄不变量，并有仿真断言检查每个尚未退休的更老 Store 均被掩码覆盖，以及有效 Load 与头部 Store 不会同时启动。

所有 D 侧 uncached/MMIO 请求，包括退出写，都先扫描所有组和路，完成全部脏行写回及 B 响应，再发送外部请求。总周期包含退出前的扫描和写回成本。测试不只检查退出结果，还在退出 AW 当拍核对外存字节，并要求前序写响应全部排空。

写回失败时完整排空已发出的整行写请求，保留整条脏行和原标签；不安装替换行，也不发送该次后续 MMIO。故障属于触发淘汰或 flush 的当前 Load/Store，无法追溯成已退休 Store 的精确异常。推测 Load 被杀时，其晚到错误只排空，不更新已复用的 ROB/PRF；保留的脏数据可在后续访问中重试。CPU 级一次性 SLVERR 注入覆盖合法 Load/Store 故障和错误路径 Load 被杀后退出重试，精确检查故障 PC、提交前缀、取消身份和外存结果。

复位按课程全系统冷复位处理，不保留脏数据；当前范围也不包含自修改代码、FENCE、缓存一致性或运行时陷阱处理。

## 时序改动的依据

V2 最差路径从 D Cache 状态驱动大量标签触发器，最小周期为 11.6592 ns。V3 把标签搬到同步 SRAM 后，第一轮达到 4.7432 ns，但集中更新 valid/dirty 的控制仍驱动数百个负载。改为逐行状态更新后，缓存路径缩短到约 2.48 ns。

随后根据实际路径逐步处理恢复信号：ROB 的空闲尾项和无效 IQ 项可以准备载荷；MDU 空闲时可以预采样输入，但仅真实握手启动状态机。MDU 原始空闲/结果状态提供给调度，真实握手仍屏蔽 reset/flush；EX 使用局部资源状态保持活跃载荷，恢复只清有效位。BTB 训练寄存一级，FIFO 输出用逐项掩码归约。

前端每个已接受取指请求已预留指令 FIFO 槽，始终满足 `queue_count + request_count <= FETCH_QUEUE_DEPTH`。因此返回接收无需再次依赖 decode/dispatch 的同拍出队结果；简化后的接收条件保持所有合法时序，并由容量断言、最小/非二次幂配置与连续重定向测试检查。

最后去除分支比较结果对 `issue_simple` 分类的伪依赖：分支/跳转无论目标是否对齐，都使用普通写回通道；只有访存的初始错误或地址未对齐会改变特殊执行通道选择。真实故障计算完全保留。原路径 `issue_a → branch_taken → target[1] → issue_simple → EX 保持` 被切断，最终从 282.02 提升到 338.96 MHz，官方程序周期不变。最终最差路径为取指 FIFO 队首经译码/分配、取指信用判断到新请求 PC 寄存器；它仍是下一阶段实际待优化项。

所有综合使用原课程 Yosys/ASAP7/OpenSTA 流程、2 ns 约束及 SRAM 模型。频率是理想时钟、无布线寄生的课程综合估算，不等于 FPGA 或流片实测频率。

## 测量口径与后续瓶颈

统一采用官方性能程序、`LATENCY=10`、动态指令数除以模拟总周期。同一组 V3 RTL 中，4 KiB 两路的 IPC 几何平均为 0.3086，四路为 0.3092：rsort 周期从 876,802 降至 859,300，但 qsort 从 432,386 小幅增至 433,877。四路收益有限，主要改善来自写回策略、并行写回与 Load 调度。

诊断轨迹新增 `MEM_RESPONSE` 与 `STORE_RETIRE`，明确区分 Store 不可撤销请求接受、Cache 返回和 ROB 退队。旧版只有请求接受事件，因此不能把 V2 的提交间隙直接称为精确 B 等待时间；Load 寿命和提交空档也不能相加当作 CPI 分解。

V3 普通命中 Load 的 issue→complete 为 3 周期，常规 refill 为 22 周期，脏 victim 为 48 周期。rsort 的 37,902 次 Load 中仍有 3,461 次付出 48 周期，qsort 的 31,033 次中有 830 次。退出写请求到最终 B 的尾部为 median 2,006、multiply 1,026、qsort 270、rsort 270、towers 886、vvadd 2,034 周期，均已计入官方总周期。

下一步优先评估已提交 Store Buffer、读写回重叠和更多数据请求并发；分支仍到提交点才恢复，median/towers 也受恢复开销影响。达到课程性能档仍需继续提高 IPC，不能仅依靠频率改进。

## 正确性验证

最终源码在 Mac 原生 Verilator 5.052 与课程 Linux Verilator 5.020 均通过 **19/19 正确性程序和 6/6 性能程序**，周期逐项一致；常规精确故障诊断两平台各 **27/27**。官方正确性中运行最长的 `correctness_pi` 为 40,365,078 周期，因此完整回归仍使用 100,000,000 周期上限。

默认配置 **31 组 × 延迟 1/10/31 = 93/93**，逐条比对 **81,588 次架构提交**；六个官方性能程序另做逐条比对，共 **374,104 次提交**。原有乱序发射、错误路径取消、迟到 Load 与 PRF 复用、预测训练/恢复、EX 写回争用及同拍唤醒覆盖全部保留。

非二次幂配置 ROB=5、PRF=37、IQ=3、LSQ=3、I/D=128 B、行=8 B、D=1 路写回、前端队列=5/在途=3/BTB=5：**62/62**，比较 **54,392 次提交**。仅此小配置豁免依赖默认窗口时序和 BTB 布局的覆盖；逐条架构比较不豁免。

写回故障注入 **9/9**，Decoder **4,035**、ALU **6,628**、M 运算 **2,257** 项及取消/背压全部通过；前端 **5** 配置、旧写穿存储 **3** 配置、新写回存储 **7** 配置通过，后者包含 1/2/4 路、16/64 B 行、长短延迟、真实四笔写信用、AW/W 独立背压、整行末字错误、全组全路 flush 与外存检查。参考模型/测量工具 **14** 项单测、全部 **31** 组 GNU 编码核对通过。

官方构建、测试、综合脚本、SRAM 模型、约束、库和测试子模块均未修改。最终综合位于 `build/v3/synth-r5/opt/`；机器可读记录保存精确参数与源码 SHA，避免把不同阶段测量拼成最终结果。
